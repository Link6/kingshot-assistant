# 房间服务

项目：`apthksvwesjebpguprvj`，组织 `Link6's Org`。创建时报价 $0/月；不升级付费计划。

仅允许 Discord 服务器 `1409235905629130915` 的成员使用房间。登录与服务器成员资格分别验证；不以客户端字段、隐藏按钮或可编辑的 user_metadata 作为权限依据。

## Discord 一次性设置

1. 在 https://discord.com/developers/applications 创建应用。
2. OAuth2 Redirects 添加 `https://apthksvwesjebpguprvj.supabase.co/auth/v1/callback`。
3. 在 Supabase Authentication → Sign In / Providers 启用 Discord，直接填 Client ID 和 Client Secret。不要将 Secret 写入仓库或聊天。
4. Authentication → URL Configuration 的 Site URL 和 Redirect URL 都填 `https://link6.github.io/kingshot-assistant/`。本地验证可额外允许 `http://localhost:4173/`。
5. 客户端请求 `guilds.members.read`，后端验证提供的 Discord token 与已认证 Supabase identity 相符，再查询指定服务器的当前成员身份。不需要机器人。

Electron 桌面端通过系统默认浏览器完成 Discord 授权，可沿用该浏览器个人资料的 Discord 登录。主进程只监听 `127.0.0.1` 的随机端口，为每次登录生成独立的随机 state，并使用 PKCE 换取会话。现有线上认证服务已验证接受该本机回调；部署到其他项目时需要确认 `http://127.0.0.1:<随机端口>/discord/callback` 可被回调。无需网页中转部署或系统协议注册。回调只接收授权码，不接收浏览器会话令牌；会拒绝错误 state、Host、方法及带 Origin 的请求。完成、取消或超时后关闭监听端口，不读取或复制浏览器 Cookie。主进程仍仅向固定的 `discord-access` 地址转发成员验证，后端继续校验 Supabase JWT、对应的 Discord identity 和指定服务器成员资格。Discord provider token 仍只保留在当前页面会话中，不保存到数据库或长期本地存储。

## 配额和权限

- 默认每人 1 个有效房间，全站最多 3 个，单房最多 30 人；6 小时后过期。
- 登录后先恢复本机记住的房间；若没有有效本地记录，按当前已验证账号查找自己创建的有效房间。入口“找回我创建的房间”可手动恢复，无需知道原房间码，不能查询其他房主。创建遇到已有房间时会恢复原房间。
- “关闭房间”和“离开房间”会请求服务器确认，即使 Realtime 断开仍可通过 HTTP 操作；失败时保留房间与房间码，允许重试。只有“返回本地（保留房间）”才仅切换本机界面，不关闭服务器房间。临时读取失败也不会清掉记住的房间码。
- 查找自己的房间是只读操作；关闭、离开不占用每分钟或全站每日共享更新额度，额度用完仍可释放房间。身份、Discord 准入和房主角色检查保持生效。
- 每人每分钟最多 60 次写入，全站每日最多 1000 次成功共享更新。
- 仅房主可任免指挥；房主和指挥可维护敌方、选择或手动添加车头，并设置各车头的集结准备时间。
- 本地和房间车头都可启用／停用。房间仅房主、指挥可操作；停用保留昵称、关联成员及时间配置，移除该车头当前任务，其他车头时刻不变。重新启用后需生成／发布新排程；停用期间关联成员更新的行军时间会保留。名单上限 30 位包含停用车头。
- 房间成员默认是 joiner，不会因填写行军时间自动进入排程。成员只更新本人的行军时间；被选为车头后，该时间自动用于车头排程。尚未填行军的车头保留为空，补全后才能排程。
- 进入房间切换到独立作战页，本地名单、排程和敌方记录保留在本地，不注入房间数据；房间内暂停本地行动声音，离开后恢复本地视图。
- 房主和指挥统一切换待命、进攻集结、防守补兵，发布全员文字指令和共享排程。普通成员无法发布、替换或校准排程。
- 防守中的敌方记录可由房主或指挥停止。停止后保留昵称和读数资料，但从有效攻击和补兵窗口中移除；重新发起需重新记录新的倒计时，不恢复旧截止时间。停止、重新记录和微调均校验记录版本，旧请求不能覆盖重新发起后的记录。
- 防守中可发布反集结：每个车头选择一波有效敌方攻击和正数命中偏移。时间由服务器按敌方、车头资料计算，拒绝客户端伪造的身份、昵称和绝对时间；只有房主／指挥可生成、微调、记录实际剩余时间、重新对齐和停止。支持复用停用车头，新增手动车头会保留资料并默认不参与进攻。反集结不改变防守模式或普通成员的补兵计算。
- 反集结按每车头一份版本化任务保存在私有房间快照，最多 30 份，读数记录使用校时后的点击时刻，逐帧计时不写入数据库。敌方修改或停止保留已记录的我方进度并提示核对；重新对齐未发起任务会重新计算开车，已记录实际进度的任务保留实际发起时刻。切换离开防守模式、或发布进攻排程，会清除旧反集结任务；保留车头名单。
- 切换到待命或防守会结束本轮可执行的进攻排程，保留车头名单。再次进攻需重新发布，避免重播已过期的开车指令。
- 已填写的行军时间和确认状态会保留；切换进攻、防守或重新发布排程不再自动要求重复确认。只有未填写，或指挥主动要求重新核对时，才需确认，读数未变可直接提交现有值。
- “我的行军时间”下提供本人手动维护的宠物预计倒计时，按 2 小时、已开启分钟数估算，结束前 5 分钟提醒。按账号保存在当前浏览器，刷新保留；不共享给他人、不持续写入数据库。宠物临近结束或结束只提示查看行军读数，不自动作废确认或强制重新填写。
- 共享开车排程包含绝对时间和独立轮次 ID，逐队支持 ±0.1/±1 秒、记录现在发起、设置实际发起时刻。调整仅影响该队，预计到达和间隙立即重算；确认行军更新会修正该成员对应的到达估计，但保留发起时刻。
- 指挥命令使用独立版本号，成员更新行军不导致指令版本冲突；同一命令、同一车头或不同轮次的过期写入仍拒绝。车头配置改变后会暂停旧排程行动提示，需指挥重新发布。
- 手动车头可不关联房间成员，其昵称、集结准备和行军时间由房主或指挥填写。移出车头名单不移除房间成员；关联成员离房后自动移出车头名单。
- 每 5 分钟重新核验 Discord 成员身份。验证过期后数据库拒绝请求；客户端不能绕过。
- Realtime 仅通知房间版本变化，不广播每帧倒计时。数据库快照包含绝对时间，客户端根据估算的服务器时差计算。
- 这些限制约束正常应用使用，不能替代平台层流量防护或保证所有 Supabase 计费项永不超额。保持免费计划，不自动升级。

## 资源

`rooms.sql` 是初始 schema，`harden-rooms.sql` 将特权例程移入非公开 schema，`configure-rally-leaders.sql` 分离房间成员和车头名单，`commanded-battle.sql` 增加指挥模式、行军核对和共享开车指令，依次执行。远端最后一份 SQL 拆为命名迁移部署表、内部命令例程及 RPC 快照，并随后完善了命令版本和已发起标记；文件记录最终状态，供新环境一次安装。现有成员默认保持 joiner，已有房间初始待命、行军待核对。远端变更需走命名 migration 并在改动前检查现有 tables。所有私有表和公开通知表开启 RLS，RPC 显式校验 auth.uid、短时 grant、房间成员及角色。Discord grant RPC 仅 service_role 可执行；内部命令例程禁止客户端直接调用。

`discord-access` 函数在服务器核验 Supabase JWT、Discord 身份及服务器成员身份。service_role 和 Discord token 不写日志；客户端只保存 publishable key。

已有环境执行 `retain-march-confirmation.sql` 更新内部指挥例程，以保留切换模式时的行军确认；新环境的 `commanded-battle.sql` 已包含该行为。

最后执行 `stop-enemy-timers.sql` 添加敌方计时启停状态并更新 RPC。快照的 `enemies` 只包含有效攻击，停止资料放在 `stoppedEnemies`，以保证旧页面也不继续计算已取消攻击。相关回滚验证见 `supabase/tests/stopped-enemies.sql`。

随后执行 `recover-owned-rooms.sql` 更新 RPC：`owned` 只读查找当前 `auth.uid()` 拥有的有效房间，再按既有成员检查返回快照；关闭、离开不受共享更新额度阻塞。该文件基于停止敌方后的完整例程，不覆盖已有计时启停和作战校准逻辑。权限、跨账号、耗尽额度后的关闭／离开及重新创建的回滚测试见 `supabase/tests/room-recovery.sql`。

最后执行 `toggle-rally-leaders.sql`，为车头添加默认启用的 `enabled` 状态，更新发布过滤和启停操作。快照 `leaders` 仅包含启用车头，`disabledLeaders` 保留停用资料，旧页面也不会继续给停用车头排程。启停校验车头版本并更新指挥版本，阻止旧发布请求；停用只取消本车头任务。权限、配置保留、发布过滤、全停用和恢复的数据库回滚验证见 `supabase/tests/disabled-leaders.sql`。

随后执行 `counter-rallies.sql` 添加有界 `rooms.counter_rows` JSON 数组和私有、禁止客户端直接调用的 `counter_mutate`。仍经原有 RPC 的身份、Discord、成员、角色、额度和房间行锁检查，不开放新表访问。快照增加 `counterRows`，旧客户端可忽略该字段。计算、权限、并发版本、实际校准、显式重新对齐、取消、验证和换轮清除测试见 `supabase/tests/counter-rallies.sql`；测试成功或失败均不保留测试用户和任务。

前端内置的官方 `@supabase/supabase-js` 版本固定为 `2.118.0`，许可证见 `dist/SUPABASE-LICENSE.txt`。Discord provider token 仅保留在当前标签页 sessionStorage 中；从 SDK 的持久化副本中移除，不上传到数据库。退出登录时清除。函数关闭网关旧 JWT 校验，入口内通过 Auth `/user` 验证每个 Supabase bearer token；没有匿名授权路径。

真实 PostgreSQL 权限测试在 `supabase/tests/rooms.sql`、`supabase/tests/leaders.sql` 和 `supabase/tests/battle.sql`，顺序执行并使用事务回滚，不保留测试用户或数据。joiner 更新行军不会使车头排程失效；车头或集结配置更改需指挥重新发布。共享倒计时按绝对时间在客户端运行，断线、核对未完成或旧配置时暂停行动提示。
