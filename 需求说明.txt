Kingshot 战术计时助手 · 需求说明

用户已确认
1. 集结计算：多个车头配合，使集结同时到达同一目标。
2. 补兵助手的主要问题：原软件用法不直观。
3. 平台：尽量跨平台。
4. 需要考虑多语言。
5. 需要支持通过 Electron 生成桌面应用，并兼容 GitHub Pages 托管网页。

实现状态
当前已实现并验证：中文网页原型、集结同步、补兵窗口、响应式布局、本地草稿保存与离线缓存。
新增规划，尚未实现：多语言切换、Electron 桌面打包、GitHub Pages 部署流程。
当前 Sites 私有试用地址与后续 GitHub Pages 是不同发布渠道；确定 GitHub 目标仓库后再配置上线。

实现选择
采用响应式网页应用，支持 Windows、macOS、Android、iOS 的现代浏览器。
计算在设备本地进行；常用输入保存在该浏览器，不需要游戏账号。
支持网页安装与静态资源离线缓存（须先通过 HTTPS 或 localhost 打开）。
电脑可直接打开 dist/index.html；手机通过发布地址使用。
首版使用手动录入，不依赖游戏接口或截图识别。

一、同步集结
每个车头录入昵称、集结准备时长、到目标的行军时长。
默认自动选择最近可执行的共同到达时刻，并为最早开车留出操作准备时间。
也可指定本地日期与共同到达时刻，精确到秒。
开车时刻 = 共同到达时刻 - 集结准备时长 - 行军时长。
按开车顺序显示名单、准确时刻和倒计时。
指定时刻使任何车头来不及时，不生成无效排程，提示原因。
修改输入后需要重新排程；旧排程显示明确提示，不静默改变正在执行的时间。

二、王城补兵
规则暂按参考软件说明：援军在相邻两波敌方攻击之间到达王城。
该规则是当前实现假设，尚未获得用户单独确认。
录入自己的行军时长和窗口两端的容错秒数。
逐个添加敌方车头；敌方集结中时录入当前准备倒计时及完整行军时长。
倒计时走到所填读数时，点击该队“记录现在”，立即开始计时。
敌方已行军时，切换“行军中”，只填当前剩余行军时间并记录。
预计攻击到达 = 点击记录的时刻 + 准备剩余 + 行军剩余。
按攻击到达时刻排序。只计算已记录队伍之间的窗口。
安全到达窗口 = [上一波到达 + 容错，下一波到达 - 容错]。
出征窗口 = 安全到达窗口 - 自己的行军时长。
默认提示窗口中点；中点已过但最晚出征尚未到时，提示“现在出征”。
无正长度安全间隔、没有足够记录、窗口已过时，明确说明。
再次记录只更新这一支队伍，其他队伍记录时刻不变。
输入错误保留上次有效记录；正在修改但尚未记录的状态明确可见。

三、交互
两个独立功能页；每页有简短步骤提示、输入区和醒目结果区。
时间输入支持秒数、小数秒、分:秒、时:分:秒和中文单位。
提供声音开关、倒计时提醒、专注模式、手机布局。
允许加载明确标记的示例；首次打开没有预填实战队伍。
保存常用参数与队伍草稿，不保存正在执行的战斗时间戳。
重新打开或刷新后，必须重新排程/记录，避免旧战况被误用。
删除与清空可确认；清空仅影响当前功能。

四、实际限制
结果依赖用户读数、点击时刻与游戏实际行军时间，不保证补兵成功。
浏览器进入后台或设备锁屏后可能暂停提醒；实战保持页面前台。
专注模式用于突出计时，不承诺浏览器跨应用置顶。
不同设备之间暂不自动同步数据。

五、验收
不同准备/行军时长的多个车头，生成的预计到达时刻相同。
可拒绝已经来不及执行的指定到达时刻。
相邻攻击差 3 秒、两端容错各 0.2 秒时，安全窗口为 2.6 秒。
窗口差值不大于两倍容错时，明确不可用。
校准一支敌方队伍不改变其他已记录队伍。
错误输入不覆盖有效记录；刷新后不恢复过期战斗计时。
电脑和窄屏手机均可完成录入、排程、记录和查看提醒。

六、多语言（新增需求）
首批建议简体中文 zh-CN、英语 en；具体首批语言范围待用户确定。
将文案集中在语言资源中，新增繁体中文、日语、韩语等语言时不改计算逻辑。
覆盖导航、表单、输入示例、校验错误、确认弹窗、动态计时提示、空状态和无障碍标签。
首次按系统/浏览器语言选择；提供手动切换并记住选择，不支持的语言回退到预设默认语言。
切换语言时保留表单草稿、有效记录、当前排程和计时，不通过刷新页面完成切换。
玩家昵称保持原文，不自动翻译。计算结果使用稳定数据结构，展示层根据语言生成文案。
时间输入统一支持纯秒数及分:秒；小数点使用 . 的示例在各语言中明确展示。
中文单位可继续作为兼容输入；英文界面补充 min、s 等直观单位示例与解析规则。
显示单位、数字与日期根据语言格式化；同步集结的时钟明确使用当前设备本地时间。
倒计时含义统一：集结页提示“发起集结”，补兵页提示“派出援军”。
语言切换不改变时区、绝对时间戳、攻击顺序或窗口边界。
界面需容纳较长译文；支持缺失翻译回退，避免显示内部键名。
验收：中文和英文完整走通两种操作流程；切换语言前后的到达时刻、窗口和记录保持不变。

七、Electron 桌面版（新增需求）
同一套网页界面、语言资源和时间计算核心，外加独立的桌面外壳。
目标平台：Windows、macOS、Linux；Electron 不用于生成 Android/iOS 应用。
桌面版将网页资源打包在应用内，基础计算不依赖联网或已部署网站。
拟优先验证 Windows 安装包/便携版；macOS 和 Linux 使用相应构建环境并分别验证。
桌面增强能力：窗口置顶、精简计时小窗、窗口位置记忆，以及计时期间的后台提醒策略。
计时不能仅依赖渲染页面的刷新频率；到期时间与界面更新分开，恢复窗口时按当前时间校准。
睡眠/唤醒后标记已过期操作，不能把错过的时机当成“现在可操作”。
桌面与网页都不把已关闭会话中的实战倒计时当成下次有效战况恢复。
桌面端开启上下文隔离和沙箱，页面不直接使用 Node.js；仅开放所需的有限桌面接口。
网页端对桌面专属能力做能力检测，避免出现无效的置顶按钮。
安装包使用独立输出目录，不与网页 dist 混放；通过 GitHub Releases 等方式分发。
正式发行另行配置平台签名与更新渠道；当前尚未生成或验证任何桌面安装包。
验收：离线启动可计算；置顶开关有效；窗口切换和唤醒不会导致错误出征提示。

八、GitHub Pages 网页托管（新增需求）
当前应用使用 HTML/CSS/JavaScript，计算无需服务器，适合静态托管。
支持两类网址：账号站点 https://<账号>.github.io/ 与项目站点 https://<账号>.github.io/<仓库名>/。
默认按项目站点设计；所有脚本、样式、图标、语言资源、manifest 和 Service Worker 兼容仓库子路径。
保留哈希导航，使直接访问与刷新 #rally、#guard 不依赖服务器路由回退。
通过 GitHub Actions 验证后上传网页 dist 目录，并部署至 Pages。
Electron 主进程、打包依赖、测试和桌面安装包不作为网页资源发布。
离线缓存名称和清理范围应按应用部署路径隔离，避免影响同一 github.io 域名下的其他项目。
本地保存的数据同样按应用隔离。网页、Electron 和不同域名上的数据默认各自保存，不承诺自动同步。
网页通过 HTTPS 首次成功加载后提供离线缓存；网页版仍需保持前台以获得可靠的及时提醒。
GitHub Pages 只运行静态网页；若未来增加账号、跨设备同步或联盟共享，需要另外设计后端。
实际部署前需确定 GitHub 账号/组织、仓库名称、仓库可见性及站点访问范围，不直接沿用 Sites 私有权限假设。
验收：根路径与仓库子路径均能加载；语言资源和离线缓存可用；手机浏览器完成两项核心计算。

九、实施顺序
1. 确定首批语言，抽离文案并完成语言切换及计时状态保持验证。
2. 完成仓库子路径与缓存隔离适配，准备 GitHub Pages 工作流。
3. 添加 Electron 外壳和桌面能力，先生成并验证 Windows 版本。
4. 在对应平台构建并验证 macOS/Linux 包；配置正式发布与签名。
